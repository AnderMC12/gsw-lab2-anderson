Paso 2.1 - Puerto 8085 en /etc/apache2/ports.conf
echo "Listen 8085" | sudo tee -a /etc/apache2/ports.conf

Paso 2.2 - Contenido del sitio
sudo mkdir -p /var/www/dulcehogar.local
sudo cp .../codigo/index.html /var/www/dulcehogar.local/
sudo cp .../codigo/pastel.svg /var/www/dulcehogar.local/
sudo chown -R www-data:www-data /var/www/dulcehogar.local

Salida de ls -la /var/www/dulcehogar.local en ese momento:
  drwxr-xr-x 2 www-data www-data 4096 Oct 24 18:25 .
  -rwxr-xr-x 1 www-data www-data 1335 Oct 24 18:25 index.html
  -rwxr-xr-x 1 www-data www-data  867 Oct 24 18:25 pastel.svg
(Los archivos quedaron con "x" porque los copié desde Windows; lo corregí
en la Fase 4 con 644.)

Paso 2.3 - Virtual Host de esta fase (/etc/apache2/sites-available/dulcehogar.local.conf):

<VirtualHost *:8085>
    ServerName dulcehogar.local
    DocumentRoot /var/www/dulcehogar.local
    <Directory /var/www/dulcehogar.local>
        AllowOverride All
        Require all granted
    </Directory>
    ErrorLog ${APACHE_LOG_DIR}/dulcehogar.local-error.log
    CustomLog ${APACHE_LOG_DIR}/dulcehogar.local-access.log combined
</VirtualHost>

Paso 2.4 - Activar y probar
sudo a2ensite dulcehogar.local.conf      -> Enabling site dulcehogar.local.
sudo apache2ctl configtest               -> Syntax OK
sudo service apache2 reload
echo "127.0.0.1 dulcehogar.local" | sudo tee -a /etc/hosts
curl http://dulcehogar.local:8085        -> devolvió mi index.html (Dulce Hogar)

Para ver el sitio desde Chrome en Windows agregué también
"127.0.0.1 dulcehogar.local" al archivo C:\Windows\System32\drivers\etc\hosts.

Preguntas
----------------------------------------------------------
1) Diferencia entre sites-available y sites-enabled
   sites-available es la carpeta donde se guardan TODOS los archivos de
   configuración de sitios, estén activos o no. sites-enabled solo contiene
   enlaces simbólicos hacia los que están activos, y Apache lee únicamente esa
   carpeta. `a2ensite` crea el enlace y `a2dissite` lo borra, sin eliminar el
   archivo original; así se puede apagar un sitio sin perder su configuración.

2) ¿Por qué configtest antes de reload?
   Porque revisa la sintaxis de todos los archivos antes de aplicar nada. Si
   hay un error (una etiqueta sin cerrar, un módulo que falta), lo veo sin
   afectar el sitio que está funcionando. Con un `restart` y una
   configuración rota, Apache podría no volver a levantar y el sitio quedaría
   caído; con configtest primero se evita ese riesgo.
